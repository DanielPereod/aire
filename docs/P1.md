# P1: exportador de escena y pases de control

Objetivo: demostrar que obtenemos del modelo 3D unos pases **exactos y alineados
píxel a píxel** con el visor de SketchUp. Es la base para P2 (render) y P3 (edición
por objeto).

## 1. Instalar la extensión

```powershell
python tools\build_rbz.py         # genera dist\aire-0.2.0.rbz
```

En SketchUp: *Extensiones > Extension Manager > Install Extension* → elige el `.rbz`.
Requiere SketchUp 2021 o posterior (por `Texture#write`).

## 2. Instalar el backend (Windows)

Con Python 3.11 o 3.12 de python.org:

```powershell
py -m venv .venv
.venv\Scripts\activate
pip install -e backend[dev]
pytest backend                    # 17 tests; los de Ruby se saltan si no hay ruby
```

## 3. Exportar y generar pases

1. Abre una escena de interior y encuadra la vista que quieres renderizar.
2. *Extensiones > AIRE > Exportar escena para render (P1)…*, elige carpeta y ancho.
3. Ejecuta el comando que muestra el aviso:

```powershell
python -m aire_backend.passes "C:\ruta\a\la\exportacion"
python -m aire_backend.mask "C:\ruta\a\la\exportacion" silla --dilate 4
```

Opciones útiles de `passes`:
- `--width 2048`: otra resolución con el mismo encuadre.
- `--section-keep auto|positive|negative`: qué lado de los planos de sección se
  conserva. `auto` oculta el lado donde está la cámara.
- `--smooth-angle 0`: desactiva el suavizado de normales.

## 4. Qué revisar

Abre `passes/overlay_viewport.png`: nuestras líneas en magenta sobre la captura de
SketchUp. **Deben coincidir exactamente.** Además:

- [ ] `overlay_viewport.png`: alineación perfecta (cámara, FOV, relación de aspecto).
- [ ] `albedo.png`: las texturas tienen escala y orientación correctas, en
      especial en caras **sin material propio** que heredan el del grupo o
      componente (ver limitaciones).
- [ ] `ids.png`: cada mueble con su color; con `mask` sale el objeto completo.
- [ ] `normal.png`: superficies curvas (sofás, lámparas) suaves y esquinas nítidas.
- [ ] `depth_control.png`: gradiente coherente, sin huecos.
- [ ] Escena con **plano de sección** activo: desaparece lo correcto.
- [ ] Etiquetas ocultas y objetos ocultos no aparecen.
- [ ] Tiempo de exportación y de `passes` en una escena grande (lo imprime el comando).

Si algo no cuadra, comparte la carpeta de exportación (o `scene.json`, `viewport.png`
y la carpeta `passes`) y la escena `.skp` si es posible.

## Limitaciones conocidas

- **UV de texturas heredadas**: si una cara no tiene material propio y hereda uno
  con textura, se asume que `PolygonMesh#uv_at` devuelve pulgadas y se divide por
  el tamaño de la textura. Hay que confirmarlo con un modelo real.
- **Cara trasera**: se usa el material trasero cuando se ve la cara trasera, pero
  con las UV de la frontal.
- **Secciones**: no se generan las tapas del corte (relleno de sección), así que
  los muros cortados se ven huecos. Se resolverá si afecta al render.
- **Perspectiva de 2 puntos o zoom 2D**: si la cámara está desplazada en 2D, el
  exportador avisa y los pases pueden no coincidir.
- **Edición de grupo abierta**: hay que cerrarla antes de exportar.
- **Luces**: SketchUp no tiene luces nativas; se exporta el sol (dirección, hora,
  ubicación). La iluminación interior la decidirá el modelo de IA, guiado por
  el prompt y las referencias.

## Formato aire-scene v1

`scene.json` (cámara, vista, sol, materiales, árbol de objetos, planos de sección)
y `geometry.bin` (buffers little-endian descritos en `scene.json.geometry.buffers`).
Unidades: metros, ejes de SketchUp (Z arriba). Lo definen
`backend/aire_backend/scene.py` y `sketchup/aire/scene_writer.rb`, y un test
ejecuta el exportador Ruby con un stub de la API para comprobar que ambos coinciden.
