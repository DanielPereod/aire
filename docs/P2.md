# P2: render IA desde los pases (ComfyUI)

Objetivo: render fotorrealista que respete la geometría del modelo, y medir esa
fidelidad para elegir modelo y ajustes con datos.

## Elección para una RTX 5060 (8 GB)

| Función | Modelo | Por qué |
|---|---|---|
| **Render base** | **Z-Image-Turbo + Fun ControlNet Union** | 6B, Apache 2.0, ~9 pasos. Control real de **profundidad y líneas** con nuestros pases (dos controles encadenados). Con 8 GB se carga en FP8. |
| Edición/referencias (P3) | FLUX.2 [klein] 4B FP8 | Cabe en 8 GB; edición con imágenes de referencia. |
| Máxima calidad | FLUX.2 [dev], Qwen-Image-Edit-2511 | Necesitan 24 GB o más: en la nube. |

Hallazgos al revisar ComfyUI (código de octubre de 2026):
- El nodo `ZImageFunControlnet` acepta también `inpaint_image` + `mask`: el mismo
  modelo podría servir para editar por objeto con la forma bloqueada (P3). Para
  eso hace falta una variante del ControlNet con canales de inpainting.
- ComfyUI ya soporta **Qwen-Image 2.1** con su propio Fun ControlNet. Será
  candidato cuando haya versiones que quepan en 8 GB.
- FLUX.2 no tiene ControlNet de profundidad en los flujos oficiales: se guía con
  imágenes de referencia, que es útil para editar pero da menos garantías
  estructurales.

**RAM:** con 8 GB de VRAM, ComfyUI descarga parte del modelo (sobre todo el
codificador de texto Qwen3 4B) a la RAM. Se recomiendan **32 GB de RAM**.

## 1. Instalar ComfyUI

ComfyUI Portable para Windows (NVIDIA) desde su GitHub, o ComfyUI Desktop.

## 2. Comprobar el hardware y descargar los modelos

```powershell
.venv\Scripts\activate
pip install -e backend
python -m aire_backend.hardware
python -m aire_backend.models download zimage-control --comfy-dir C:\ruta\a\ComfyUI
```

Descarga aproximadamente 20–25 GB: Z-Image-Turbo bf16 (se convierte a FP8 al cargar),
Qwen3 4B, VAE y ControlNet Union. Si usas ComfyUI Portable, la carpeta es la que
contiene `models\`, normalmente `ComfyUI_windows_portable\ComfyUI`.

## 3. Renderizar

```powershell
# un render
python -m aire_backend.render "C:\ruta\exportacion" --prompt "salón nórdico, luz de tarde"

# barrido: 8 combinaciones (profundidad 0.6/0.9 × líneas 0/0.5 × partir del albedo sí/no)
python -m aire_backend.render "C:\ruta\exportacion" --prompt "salón nórdico" --sweep --seed 1234
```

Cada ejecución crea `renders\<fecha>\` con:
- `render_XX.png`
- `meta.json`: prompt, semilla, ajustes, tiempo y fidelidad.
- `sweep.png`: hoja de contactos con las puntuaciones, al usar `--sweep`.

El prompt se completa solo con los objetos visibles y sus materiales, por
ejemplo "Mesa comedor (Nogal), Suelo (Tarima roble)". Con `--no-auto-prompt` se
usa solo tu texto.

Ajustes principales:
- `--depth`: cuánto manda la profundidad (la forma).
- `--lines`: cuánto mandan las aristas (bordes de muebles y carpinterías).
- `--denoise 0.9`: parte del albedo, para que los colores y materiales sigan el modelo.
- `--weight-dtype default`: carga en bf16 (solo con ≥ 16 GB).
- `--dry-run`: genera el `workflow.json` sin ComfyUI. Se puede abrir en ComfyUI
  para inspeccionarlo.

## Métrica de fidelidad

`python -m aire_backend.fidelity render.png passes_WxH` calcula:
- **recall**: fracción de las líneas del modelo que aparecen en el render (±3 px).
  Más alto es mejor: no se ha perdido ni deformado estructura.
- **spurious**: bordes fuertes del render lejos de cualquier línea del modelo.
  Incluye texturas, así que solo sirve para **comparar** ajustes entre sí. Un salto
  grande suele indicar objetos o huecos inventados.
